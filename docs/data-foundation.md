# Assessment data contract

The operator publishes a hash-bound market index outside Git. Each origin-to-target
price transition binds its complete candidate features, supported price history,
source and preparation context, and any official outcomes or received Cito report.
The viewer reads those artifacts and never opens the operating database.

Original bytes, identifiers, exact source money, missingness and provenance remain
immutable. Source money is integer ore; displayed AIP and model amounts use DKK per
package. Receipt, download, interpretation, preparation and assessment times are
different facts. A filename or file modification time is not authoritative context.

Cito validation requires supported columns, package identity, valid classifications,
the actual current/target transition and reported receipt context. Valid matching
advance codes use the advance route; missing or unusable codes use current-only
components. The no-Cito comparison uses the same population, market snapshot and
target with advance information excluded. Uploading a report does not mean every
package used Cito.

Inference verifies the retained protocol's model and dependency hashes, ordered
features, categorical columns, environment, cutoffs and saved calibration. The broad
probability reference is `summer-fresh-current` / `summer-fresh-advance`, with the
retained equal-size/package fallbacks. The broad components use three years and
the July 1, 2026 cutoff; older fallback cutoffs remain unchanged. Calibration uses
evidence mature before September 1. Amount pairs are `summer-rmse-*`,
`summer-amount-6y-*` and `summer-amount-full-*`, all at the July cutoff. These names
identify retained artifacts, not an instruction to train them.

The fixed policy requires rise probability at least 35%, fall probability at most
10%, and caps the selected population at 10% using the retained deterministic
ranking. The interface displays the first 50 qualifying predictions. It never pads
the queue or replaces a candidate with an unknown outcome. Full predictions,
routing and exclusions remain saved. Direction and amount evaluation are separate.

Features must be causal at the origin. `research.market_inputs.advance_checkpoint`
can advance a prepared checkpoint only to the immediately supported calendar origin
and supplied official snapshot; it does not acquire sources, rebuild the training
bundle or fit models. The preserved operator workspace handles database ingestion,
publication and backup separately. Supplier files alone do not establish a usable
predictive signal, dated identity join or negative evidence of disruption.

Every assessment binds source/model/context identities and captured service code.
Identical retries reuse verified work; changed context produces a separate result.
Native locks serialize jobs, and durable status survives browser reconnection.
Failure preserves the last successful result. Notes bind to assessment and package.
Reports verify saved values and are generated without inference or database writes.

Private model/protocol bundles are prerequisites, not repository assets. Retained
absolute pins must resolve to verified originals or a separately verified recovery;
never rewrite accepted evidence simply to make another machine pass validation.
